# aidoc-kit

aidoc-kit (https://www.npmjs.com/package/aidoc-kit, MIT) writes persistent context for
AI agents into a JS/TS codebase: `@ai-*` blocks in each file, an `AGENTS.md` entry
point, chunk summaries of large files and an enriched code graph. This skill tells you
how to use that context. It does not replace the CLI: the files below only exist once
the developer has run it.

## 1. Detect what the project has

Check the project root, without reading large files in full:

| File or folder | Produced by | What it gives you |
|---|---|---|
| `AGENTS.md` | `aidoc-kit scan` | Agents, domains, runtime map, project rules |
| `aidoc-graph.json` | `aidoc-kit index` | Role, criticality, dependents and dependencies per file |
| `.codemod/chunks/*.md` | `aidoc-kit chunk` | Structured summary of every file over 150 lines |
| `@ai-*` blocks in sources | `aidoc-kit scan --write` | Per-file context, cascade, validation command |

Read `AGENTS.md` first. Manual content outside its generated block is written by the
developer and takes precedence over generated content.

If the `aidoc-kit` MCP server is connected (tools `context_for_edit`, `file_info`,
`dependents`, `dependencies`, `critical_files`, `read_chunk`, `graph_status`), use it:
call `context_for_edit` before modifying any file and `read_chunk` instead of reading a
large file in full. It applies sections 2 to 4 below in one call, and also lists places
that name the file as text. Otherwise, follow sections 2 to 4 by hand. The developer
can connect it with `claude mcp add aidoc-kit -- npx aidoc-kit mcp` (Claude Code) or an
`mcp.json` entry running `npx aidoc-kit mcp`.

## 2. Query the graph, never load it

`aidoc-graph.json` grows with the project. Query it with one-liners:

```bash
# One file's entry (role, criticality, tags)
node -e "const g=require('./aidoc-graph.json');console.log(g.files.find(f=>f.file==='src/foo.ts'))"

# Who depends on a file
node -e "const g=require('./aidoc-graph.json');console.log([...new Set(g.edges.filter(e=>e.to==='src/foo.ts').map(e=>e.from))])"

# Most critical files
node -e "const g=require('./aidoc-graph.json');g.files.filter(f=>f.criticality>=55).forEach(f=>console.log(f.criticality,f.file))"
```

Rules:

- Before modifying a file, look up its entry. If `criticalityLevel` is `high` or
  `critical`, read every dependent file before editing.
- Never import a file with `role: server` from client code.
- The graph only sees imports, calls and references. Coupling through file contents
  (a JSON or config file naming a path, a script reading a file as text, a string
  lookup) is invisible. A low score does not prove a low impact: search for the file
  name as a string too.
- The graph reflects the code at `generatedAt`. Trust it when
  `npx aidoc-kit index --check` passes (usually in CI). Otherwise, tell the developer
  it may be stale and ask them to run `npx aidoc-kit index --incremental`.

## 3. Large files: read the chunk first

For any source file over 150 lines, read `.codemod/chunks/<same path>.md` before
opening the source (for example `src/contexts/auth-context.tsx` ->
`.codemod/chunks/src/contexts/auth-context.tsx.md`). It lists public exports, critical
imports, structure, functions and importers. Then read only the part of the source you
need. If the chunk is missing, ask the developer to run `npx aidoc-kit chunk`.

## 4. Honour the @ai-* block of each file

| Tag | What to do |
|---|---|
| `@ai-context` | Read it before the code: it says what the file does and exposes |
| `@ai-when-modifying` | Follow these steps when editing the file |
| `@ai-cascade` | Check each listed file after your change |
| `@ai-validate` | Run this command after modifying the file and report the result |
| `@ai-always` / `@ai-never` | Invariants and prohibitions: never break them silently |
| `@ai-runtime` | Execution context (server only, client only, universal) |
| `@ai-agent`, `@ai-agents-related` | Domain labels: read related domains' files when relevant |

When you add a new exported function or change what a file exposes, update its
`@ai-context` and `@ai-cascade` by hand if they become wrong, and say so.

## 5. Commands belong to the developer

Do not run `aidoc-kit` commands that write files (`scan --write`, `chunk`, `index`,
`enrich`, `fix`) unless the developer asks. They can rewrite many files at once and
`enrich` may call a paid LLM API. Report what is missing and suggest the command.

Read-only commands are fine when useful: `npx aidoc-kit scan --dry`,
`npx aidoc-kit index --check`.

## 6. Setting up aidoc-kit (only when asked)

```bash
pnpm add -D aidoc-kit          # or npm i -D / yarn add -D
npx aidoc-kit init             # detects the stack, writes aidoc.config.ts
npx aidoc-kit scan --dry       # preview @ai-* blocks
npx aidoc-kit scan --write     # write blocks and AGENTS.md
npx aidoc-kit chunk            # summarise files over 150 lines
pnpm add -D @colbymchenry/codegraph && npx aidoc-kit index   # optional graph, Node >= 22.5
```

If `aidoc-graph.json` is committed, recommend adding `npx aidoc-kit index --check` to CI
so a stale graph fails the build. Repositories that must not carry agent instruction
files can use `--no-agents-md`.
